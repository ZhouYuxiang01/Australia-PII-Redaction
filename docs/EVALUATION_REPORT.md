# Evaluation Report

## Scope

This report covers the final deployable route:

```text
OPF candidate detector + Qwen 3.5 9B hard-negative span-head + risk/redaction policy
```

The system is evaluated as both component models and an end-to-end redaction
wrapper. Historical ablations are included only as context and are not presented
as the final deployed model score.

## Methodology

The evaluation uses span-level PII data generated by the reproducible training
pipeline in `pii_training_prep_v3_2/`. The final route separates evaluation into
three levels:

1. OPF span detection: verifies whether likely PII spans can be found with high
   recall.
2. Qwen span-head classification: verifies whether OPF/fallback candidate spans
   are assigned the correct PII type or `NON_PII`.
3. End-to-end wrapper evaluation: verifies final redaction behavior after policy,
   thresholds, deterministic rescue, overlap handling, and review decisions.

The end-to-end wrapper evaluation uses exact-span matching and overlap matching.
Exact matching requires the predicted span boundaries and type to match the gold
span exactly. Overlap matching allows boundary overlap and is useful for measuring
whether the system finds the sensitive region even when boundaries differ.

## Robustness and Edge Cases

The system includes explicit mechanisms for common failure modes:

| Case | Handling |
|---|---|
| Ambiguous numeric strings | Qwen type probabilities, context checks, and hard-negative drop rules reduce false positives. |
| Stable identifier formats | Deterministic rescue rules support TFN, Medicare, passport, bank account, payment card, email, phone, UAC ID, USI, and similar formats. |
| Low-confidence spans | Policy routes uncertain cases to `review` rather than silently ignoring them. |
| OPF/Qwen type disagreement | Top-k distribution, source, confidence, and context are used by policy to choose redact/review/ignore. |
| Overlapping spans | Policy keeps the longer span, then the earlier span on ties. |
| OCR-like noisy input | File extraction feeds normalized text through the same backend; noisy boundaries may still reduce exact-match score. |
| Hard negatives | Candidate-level `NON_PII` examples and policy filters reduce redaction of non-sensitive ticket numbers, room numbers, and fake IDs. |

## Known Limitations

- Exact span boundaries remain harder than overlap detection, particularly for
  addresses, compound names, OCR-like noise, and merged document fragments.
- Some fields are context-sensitive. Numeric identifiers, phone-like strings, and
  internal references can require review when context is weak.
- The Qwen backbone must be available locally and is not included as a project
  artifact.
- Visual-text transcription quality can limit performance on images and scanned
  PDFs.
- Production deployments should add authentication, TLS termination, request-size
  controls, and sensitive-log handling at the hosting layer.
